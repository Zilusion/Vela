# Vela
![image](https://github.com/user-attachments/assets/896c2d5e-e1fe-4187-a2a0-1fd17a13c6fe)

## Цель проекта

Реализация адаптивной верстки шапки и многоуровневого меню для веб-сайта согласно предоставленным макетам Figma. Основное внимание уделено чистой структуре, семантике, адаптивности и современным подходам к верстке без использования CSS-фреймворков.

## Демо

[Ссылка на Демо](https://zilusion.github.io/Vela/)

## Реализованные Возможности

*   **Адаптивная шапка:** Корректное отображение на десктопных и мобильных устройствах (< 768px) с изменением расположения и видимости элементов.
*   **Многоуровневое Мега-меню:**
    *   **Desktop:** Отображение подкатегорий при наведении (`hover`) на пункты основного меню, поддержка нескольких уровней вложенности с отображением панелей рядом.
    *   **Mobile:** Отображение меню по клику на кнопку-"бургер", реализация паттерна "drilldown" (постраничная навигация) по клику на пункты с подкатегориями, наличие кнопки "Назад".
*   **Sticky Header:** Часть шапки (центральный блок) "прилипает" к верху экрана при прокрутке страницы вниз.
*   **Компенсация скроллбара:** При открытии мобильного меню на не-тач устройствах добавляется `padding-right` к `body` для предотвращения "прыжка" контента.
*   **SVG Спрайты:** Автоматическая генерация SVG-спрайтов двух типов из исходных иконок с помощью кастомного Vite-плагина.
*   **Анимации:** Плавные CSS-переходы для открытия/закрытия меню, переключения панелей и эффектов наведения.
*   **Современные технологии:** Использование Vite, Pug, SCSS, БЭМ.

## Технологии и Подходы

*   **HTML:** Сгенерирован с помощью шаблонизатора **Pug**.
*   **CSS:** Написан с использованием препроцессора **SCSS** (синтаксис Sass).
    *   **Методология:** **БЭМ** (Block, Element, Modifier) для именования классов.
    *   **Адаптивность:** Подход **Desktop-first** с использованием `@media` запросов для мобильной версии (breakpoint `768px`).
    *   **Layout:** Использование **Flexbox** и **Grid Layout** для построения сеток и расположения элементов.
*   **JavaScript:** Нативный JavaScript (ES6+) для:
    *   Управления состоянием и видимостью меню (открытие/закрытие).
    *   Обработки событий (`click`, `mouseover`, `mouseleave`, `resize`, `scroll`).
    *   Реализации логики переключения панелей в меню (desktop hover, mobile drilldown).
    *   Управления "залипанием" части хедера (`IntersectionObserver`).
    *   Динамического расчета высоты хедера для позиционирования меню.
    *   Компенсации скроллбара.
*   **Сборка:** **Vite** - современный и быстрый сборщик проектов.
*   **Шаблонизатор:** **Pug** - для упрощения HTML-разметки, переиспользования компонентов (миксины) и уменьшения дублирования кода.
*   **SVG:** Использование SVG-спрайтов для иконок, генерируемых кастомным Vite-плагином.

## Установка и Запуск

**Требования:**
*   Node.js (версия 16 или выше рекомендуется)
*   npm или yarn

**Инструкции:**

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <url-вашего-репозитория>
    cd <папка-проекта>
    ```
2.  **Установите зависимости:**
    ```bash
    npm install
    # или
    yarn install
    ```
3.  **Запуск в режиме разработки:**
    Запускает локальный сервер Vite с горячей перезагрузкой (Hot Module Replacement). SVG спрайты будут сгенерированы при первом запуске и при изменении иконок в `public/assets/icons/`.
    ```bash
    npm run dev
    # или
    yarn dev
    ```
    Откройте браузер по адресу, указанному в консоли (обычно `http://localhost:5173`).

4.  **Сборка для продакшена:**
    Собирает оптимизированные и минифицированные файлы в папку `dist/`.
    ```bash
    npm run build
    # или
    yarn build
    ```
    Результат сборки будет находиться в папке `dist`.

## Ключевые Решения и Пояснения

### Использование Vite

Vite выбран в качестве сборщика благодаря его **скорости** и **современному подходу**. Он использует нативные ES-модули во время разработки, что обеспечивает мгновенный запуск сервера и быструю горячую перезагрузку (HMR). Конфигурация Vite часто проще, чем у Webpack, и он имеет отличную экосистему плагинов для интеграции с Pug, SCSS и другими инструментами.

### Использование Pug

HTML-шаблонизатор Pug был использован для **значительного упрощения и структурирования HTML-разметки**. Основные преимущества в данном проекте:

1.  **DRY (Don't Repeat Yourself):** Сложные компоненты, такие как пункты меню, панели, кнопки и иконки, были вынесены в **миксины** (`src/template/mixins/`). Это позволяет определять структуру компонента один раз и переиспользовать его многократно.
2.  **Управление адаптивностью:** Адаптивный дизайн часто требует, чтобы одни и те же элементы (например, переключатель языка, кнопки действий, категории) отображались в разных местах DOM-дерева на десктопе и мобильных устройствах (в основной шапке vs. внутри выезжающего меню). Без шаблонизатора это привело бы к **массивному дублированию HTML-кода**. Pug миксины позволяют вставлять один и тот же компонент в разные места, передавая ему разные параметры (например, дополнительные БЭМ-классы для контекста: `header__lang-switcher` и `mobile-menu__lang-switcher`).
3.  **Читаемость:** Синтаксис Pug, основанный на отступах, делает структуру HTML более наглядной и менее загроможденной тегами.

### JavaScript Подход

Поскольку использование тяжелых фреймворков было нежелательно, был выбран подход с использованием **нативного JavaScript**. Основные задачи, решаемые JS:

*   **Управление состоянием меню:** Отслеживание состояния (открыто/закрыто), управление классами (`is-active`, `is-visible`) для отображения и анимации.
*   **Навигация в мобильном меню:** Реализация логики "drilldown" с использованием стека (`navigationStack`) для отслеживания пути пользователя и работы кнопки "Назад".
*   **Динамическое позиционирование:** Вычисление высоты хедера (`headerHeight`) и установка CSS-переменной или прямого стиля `top` для корректного позиционирования выпадающего меню на десктопе.
*   **Sticky Header Logic:** Использование `IntersectionObserver` для отслеживания момента, когда нужно применить класс "залипания" к хедеру, что является более производительной альтернативой обработчику `scroll`.
*   **Компенсация скроллбара:** Динамическое добавление/удаление `padding-right` для `body` при открытии/закрытии меню на не-тач устройствах.
*   **Синхронизация кнопки:** Обновление состояния кнопки открытия/закрытия меню (класс, `aria-expanded`).

### Адаптивная стратегия

Использован подход **Desktop-first**. Базовые стили описывают десктопное состояние. Медиа-запрос (`@include mixins.media-md`) используется для переопределения стилей для мобильных устройств (< 768px), включая изменение `display`, `position`, `transform` и скрытие/показ элементов. Дублирование элементов, необходимых и на десктопе, и в мобильном меню, реализовано через вызов соответствующих Pug миксинов в разных местах структуры.
